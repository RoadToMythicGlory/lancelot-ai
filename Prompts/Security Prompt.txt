====================================================================
1) SECURITY GOAL
====================================================================
Provide TRUE END-TO-END ENCRYPTION for chat messages such that:

- Messages are encrypted on the sender’s client.
- Messages are decrypted ONLY on the recipient’s client(s).
- The server, database, logs, and AI-agent service NEVER see plaintext.
- Encryption applies to:
  - Human ↔ Human
  - Human ↔ AI Agent
  - AI Agent ↔ Human

The AI Agent must behave like a human participant:
- It owns cryptographic keys.
- It decrypts messages locally before inference.
- It encrypts responses before sending.

2) THREAT MODEL (ASSUME)
====================================================================
Protect against:
- Database compromise

- Admin-level read access

Out of scope:

====================================================================
3) CRYPTOGRAPHIC APPROACH (REQUIRED)
====================================================================
Use a modern, audited scheme (NO custom crypto):

- Key Exchange:
  - X25519 (Diffie-Hellman)
- Message Encryption:
  - AES-256-GCM or ChaCha20-Poly1305
- Identity Keys:
  - Long-term identity key per user (including AI agent)
- Session Keys:
  - Per conversation or per session
- Key Rotation:
  - Periodic rotation without breaking sessions

All crypto must be implemented using:
- libsodium / tweetnacl / WebCrypto (depending on environment)
- NEVER roll your own primitives

====================================================================
4) KEY MANAGEMENT RULES
====================================================================
- Each user (including AI agent) has:
  - Identity key pair
  - Device/session keys
- Private keys NEVER leave the client or AI-agent service memory.
- Server stores ONLY:
  - Public keys
  - Encrypted payloads
  - Metadata (timestamps, sender ID, conversation ID)

AI Agent specifics:
- The AI agent generates and stores its private key securely on startup.
- Keys are persisted encrypted at rest (env-based or vault-based).
- The AI agent decrypts messages only inside the ai-agent service.

====================================================================
5) MESSAGE FLOW (E2EE)
====================================================================
1) Sender:
   - Encrypts message payload client-side.
   - Sends encrypted blob + metadata.

2) Server:
   - Routes messages blindly.
   - Cannot inspect content.
   - Cannot log plaintext.

3) Recipient:
   - Decrypts message locally.

4) AI Agent:
   - Receives encrypted message.
   - Decrypts inside ai-agent service.
   - Processes intent/tools.
   - Encrypts response before sending back.

====================================================================
6) AI AGENT CONSTRAINTS UNDER E2EE
====================================================================
- The AI agent must:
  - Never log decrypted message content.
  - Only log hashes / message IDs for observability.
  - Explicitly wipe decrypted buffers after use.
- Tool outputs are encrypted before leaving the agent.
