SECTION 1: ALL EXCEL PARSERS IN THE APPLICATION
================================================================================

The application contains several Excel-related components spread across the
excel-parser microservice, the api-gateway, and the web frontend. Below is a
complete inventory of every parser, where it lives, what it does, and how data
flows through it.

--------------------------------------------------------------------------------
1.1  BROADCAST SCHEDULE PARSER (Primary / Active Parser)
--------------------------------------------------------------------------------

FILE:  services/excel-parser/src/broadcast-schedule-parser.ts
CLASS: BroadcastScheduleParser
STATUS: Active — this is the main Excel parser used in production.

PURPOSE:
  Reads an uploaded .xlsx or .xls file containing a Hebrew broadcast schedule
  (typically from Channel 1 / Sport Channel operations), extracts every row into
  a structured ParsedBroadcastEvent object, and returns them as JSON.

LIBRARY USED:
  - xlsx (SheetJS) v0.18.0  — imported as `import * as XLSX from 'xlsx'`
  - No other Excel libraries are used (no exceljs, papaparse, csv-parse, etc.)

HOW IT WORKS (STEP-BY-STEP):

  1. READING THE WORKBOOK
     The parser receives a raw Buffer (from multer memory storage).
     It calls XLSX.read() with options:
       - type: 'buffer'
       - cellDates: true         (parse date cells as JS Date objects)
       - dateNF: 'dd/mm/yyyy'    (date number format for Israeli dates)
       - cellNF: true             (preserve cell number formats)
       - raw: false               (return formatted strings, not raw values)

  2. SELECTING THE SHEET
     Only the FIRST worksheet is used: workbook.SheetNames[0].

  3. CONVERTING TO JSON
     XLSX.utils.sheet_to_json() converts the sheet into an array of objects.
     Each object's keys are the header row values (Hebrew column names).
     Options: raw: false, dateNF: 'dd/mm/yyyy', defval: '' (empty default).

  4. ROW-BY-ROW PARSING (parseRow method)
     For each row, the parser:

     a) COLUMN MAPPING — Maps Hebrew column headers to English field names:
        Hebrew Header            ->  English Field
        ─────────────────────────────────────────────
        שעה (Hour)               ->  time
        תאריך (Date)             ->  date
        ערוץ (Channel)           ->  channel
        סוג (Type)               ->  eventType
        אירוע (Event)            ->  eventName
        מיקום (Location)         ->  location
        הערות (Notes)            ->  notes
        יום (Day)                ->  day
        שבוע (Week)              ->  week
        KO / TO                  ->  koTime
        ענף (Sport)              ->  sport
        ליגה/ענף (League/Sport)  ->  league
        ליגה/תחרות (League/Comp) ->  league
        שלב (Stage)              ->  stage
        מארחת / מאירח (Host)     ->  homeTeam
        אורחת (Away)             ->  awayTeam
        ישיר (Live)              ->  live
        סיום (End)               ->  endTime
        כ"ס / פטיליות            ->  subtitles
        ערוץ מקביל               ->  parallelChannel
        5 SPORT 4K / CHANNEL 1 4K  ->  channel1_4k
        שעת שידור (Broadcast hr) ->  time
        שידור (Broadcast)        ->  eventName
        משחק (Game)              ->  gameName
        מקום שידור               ->  location
        עורך (Editor)            ->  editor
        מפיק (Producer)          ->  producer
        איש VTR (ריפליי)         ->  vtrOperator
        טכנאי שידור / במאי       ->  technicalDirector
        שדר + פרשן               ->  commentators
        שדר קוים                 ->  lineCommentator

     b) HEBREW METADATA COLLECTION
        Any column NOT in the mapping table is preserved as "Hebrew metadata."
        Empty values, dashes, nulls are skipped. This metadata is stored in
        metadata.rawHebrewData and metadata.raw for the UI.

     c) TIME EXTRACTION (extractTime / parseTimeValue)
        Supports multiple formats:
        - Excel decimal time (0.0-1.0, fraction of day → HH:MM)
        - String "HH:MM" format
        - Hebrew time ("14:30 שעה")
        - AM/PM format ("2:30 PM")
        - JavaScript Date objects (from cellDates: true)

     d) DATE EXTRACTION (extractDate / normalizeDate)
        Supports:
        - String dates: DD/MM/YYYY, DD.MM.YYYY, DD-MM-YYYY (2 or 4 digit year)
        - Excel serial date numbers (days since 1899-12-30)
        - JavaScript Date objects
        - Falls back to today's date if no date found

     e) CHANNEL EXTRACTION (extractChannel / normalizeChannelToHebrew)
        Maps English channel names to Hebrew:
          5 SPORT / SPORT / CHANNEL1         ->  CHANNEL 1
          5 LIVE / LIVE / SPORT LIVE       ->  CHANNEL 4
          5 PLUS / PLUS / SPORT PLUS       ->  CHANNEL 2
          5 STARS / STARS / SPORT STARS     ->  CHANNEL 5
          5 GOLD / GOLD / SPORT GOLD       ->  CHANNEL 3
          5 SPORT 4K / SPORT 4K            ->  CHANNEL 1 4K
        Default channel: CHANNEL 1

     f) TITLE BUILDING
        Constructs a title from: sport + league + stage + "homeTeam vs awayTeam"
        Falls back to the raw event name or "אירוע ללא שם" (Untitled Event)

     g) DEPARTMENT METADATA CATEGORIZATION (categorizeHebrewMetadata)
        Distributes Hebrew columns into department buckets based on keywords:
          broadcastArray:     שידור, מערך, עורך, מפיק, טכנאי, שדר, VTR, במאי, פרשן
          mcr:                מקור, גיבוי, מכשירים, ניתובים, MCR, ניתוב
          externalBroadcasts: הפקה, צוות, ציוד, צילום, חוץ
          closedCaptions:     כתוביות, תרגום, נגישות, כ"ס
          warehouse:          מחסן, ציוד, פריטים, ברקוד
          playout:            קליטה, GMT, סינופסיס, פלייאאוט, שידור חוזר
        Unmatched columns go to ALL departments to avoid data loss.

  5. OUTPUT STRUCTURE (ParsedBroadcastEvent)
     {
       title: string,                    // Built from sport/league/teams
       startTime: "HH:MM",              // Parsed time
       koTime?: "HH:MM",                // Kick-off / Tip-off time
       endTime?: "HH:MM",               // End time
       date: "DD/MM/YYYY",              // Normalized date
       channel: "CHANNEL 1",              // Hebrew channel name
       eventType: "live" | "recorded",  // Based on "ישיר" column
       location?: string,               // Studio/stadium
       notes?: string,                  // Free text
       metadata: {
         departments: {
           broadcastArray: { customData: {...} },
           mcr: { customData: {...} },
           externalBroadcasts: { customData: {...} },
           closedCaptions: { customData: {...} },
           warehouse: { customData: {...} },
           playout: { customData: {...} }
         },
         rawHebrewData: { ... all unmapped Hebrew columns },
         raw: { ... alias for rawHebrewData },
         eventDetails: {
           sport, league, stage, homeTeam, awayTeam,
           koTime, endTime, subtitles, parallelChannel,
           channel1_4k (boolean), live
         }
       }
     }

  6. DEBUG OUTPUT
     After parsing, saves all events as JSON to:
       services/excel-parser/temp/broadcast-events-{timestamp}.json

  7. ERROR HANDLING
     - Per-row errors are collected into an errors[] array
     - Rows without time or date are skipped (not errors)
     - Full file-level parsing errors return success: false

SECTION 2: BROADCAST EVENT BATCH CREATION — UI + BACKEND
================================================================================

The system supports two ways to batch-create broadcast events:
  A) Manual grid entry (BatchEventCreator — spreadsheet-like UI)
  B) Excel file import (upload .xlsx → parse → create)

Both paths converge on the same backend save mechanism.

--------------------------------------------------------------------------------
2.1  DATA MODEL (MongoDB)
--------------------------------------------------------------------------------

FILE: services/api-gateway/src/models/broadcast.models.ts

Interface: IBroadcastEvent extends Document
  - eventNumber: number (auto-incremented, unique)
  - title: string (max 500 chars)
  - hebrewTitle?: string
  - description?: string
  - eventType: 'live' | 'recorded' | 'remote' | 'studio'
  - status: 'planned' | 'confirmed' | 'in_progress' | 'completed' | 'cancelled'

  - koTime?: Date (kick-off / tip-off time)
  - channel: string
  - parallelChannel?: string

  - live: boolean (default false)
  - metadata: Mixed (flexible JSON — stores department data, import info, etc.)
  - (many more fields: sport, league, teams, etc.)

--------------------------------------------------------------------------------
2.5  BACKEND SAVE MECHANISM (handleBatchSave)
--------------------------------------------------------------------------------

FILE: apps/web/src/app/broadcast-planning/page.tsx

The handleBatchSave function is the SHARED save path for both grid entry
and Excel import.

ALGORITHM:
  1. Loops through ALL events SEQUENTIALLY (one at a time)
  2. For each event:
     a. Builds an input object with:
        - title (from sport + league + teams, or "שידור חי/מוקלט DD/MM HH:MM")
        - eventType: defaults to 'recorded'
        - startTime: ISO string
        - endTime: ISO string (or startTime + 2 hours)
        - koTime: ISO string (if available)
        - channel: Hebrew channel name
        - parallelChannel, sport, league, stage, homeTeam, awayTeam
        - channel1_4k, live, subtitles
        - metadata: any extra data from the parsed event
     b. Calls GraphQL mutation: CREATE_BROADCAST_EVENT_WITH_OVERLAP_CHECK
        with variables: { input, forceCreate }
     c. Passes refetchQueries: ['GetBroadcastEvents', 'GetBroadcastEventsCalendar']
     d. awaitRefetchQueries: true
     e. Collects result into results[]
     f. WAITS 800ms between each event (setTimeout) to avoid rate limiting
  3. After all events processed:
     a. Checks if any result has overlaps (overlapCheck.hasOverlaps)
     b. If overlaps exist AND forceCreate was false:
        - Shows a modal: "נמצאו חפיפות בזמנים, האם ליצור בכל זאת?"
        - On confirm: re-calls handleBatchSave(events, true) with forceCreate=true
     c. If no overlaps or forceCreate was true:
        - Shows success message: "נוצרו בהצלחה N אירועים"
        - Refetches broadcast events

IMPORTANT NOTES:
  - Each event is created with a SEPARATE GraphQL mutation call (not bulk)
  - The 800ms delay means 100 events take ~80 seconds to create
  - The web app does NOT use the bulk mutations (createBroadcastEventsFromExcel)
    that exist in the API gateway — it uses per-event creation instead
  - Excel imports use forceCreate=true by default (overlap prompt was already
    shown during the Excel import confirmation)

--------------------------------------------------------------------------------
2.6  BACKEND: OVERLAP CHECK ENGINE
--------------------------------------------------------------------------------

FILE: services/api-gateway/src/resolvers/broadcast-enhanced.ts
FUNCTION: checkChannelOverlaps

PURPOSE: Before creating an event, checks if any EXISTING events overlap
on the same channel(s) during the same time window.

ALGORITHM:
  1. Collects channels to check (main channel + parallelChannel)
  2. Queries MongoDB for BroadcastEvent documents where:
     - channel is in channelsToCheck
     - startTime < newEvent.endTime AND endTime > newEvent.startTime
     - status is NOT 'cancelled'
     - Excludes the current event ID (for updates)
  3. Returns array of ChannelOverlap objects with details about conflicts

--------------------------------------------------------------------------------
2.7  BACKEND: PER-EVENT CREATION (createBroadcastEventWithOverlapCheck)
--------------------------------------------------------------------------------

FILE: services/api-gateway/src/resolvers/broadcast-enhanced.ts

FLOW:
  1. Validates input (title, startTime, endTime required)
  2. Runs checkChannelOverlaps()
  3. If overlaps found AND forceCreate=false:
     - Returns: { success: false, event: null, overlapCheck, requiresConfirmation: true }
  4. If no overlaps OR forceCreate=true:
     - Creates new BroadcastEvent document
     - Sets auto-incrementing eventNumber
     - Saves to MongoDB
     - Publishes 'BROADCAST_EVENT_UPDATED' via PubSub (for live subscriptions)
     - Returns: { success: true, event, overlapCheck, requiresConfirmation: false }

--------------------------------------------------------------------------------
2.8  BACKEND: BULK MUTATIONS (Defined but not used by web UI)
--------------------------------------------------------------------------------

FILE: services/api-gateway/src/resolvers/broadcast-enhanced.ts

MUTATION: createBroadcastEventsFromExcel(events[])
  - Loops events, parses DD/MM/YYYY date + HH:MM time
  - Creates BroadcastEvent per event, saves to MongoDB
  - Sets metadata.importedFromExcel=true, metadata.importedAt=now
  - Publishes PubSub notification per event
  - Returns: { success, eventsCreated, errors[], events[] }

MUTATION: createBroadcastEventsFromExcelWithOverlapCheck(events[], forceCreate)
  - Pre-checks overlaps for ALL events before creating any
  - If overlaps and !forceCreate: returns requiresConfirmation=true, no saves
  - If forceCreate: creates all events
  - Returns: same shape + overlapCheck details

These mutations are DEFINED in mutations.ts on the client side but are NOT
imported or called by any .tsx component. The web app uses the per-event
mutation in a loop instead.

3.5  SOCKET.IO SERVER (Real-Time Backend)
--------------------------------------------------------------------------------

FILE: services/api-gateway/src/socket/chat-socket.ts

SETUP:
  - Created with setupChatSocket(httpServer) in api-gateway/src/index.ts
  - Path: /socket.io
  - Transports: websocket + polling
  - CORS: Dynamic based on CORS_ALLOWED_ORIGINS config
  - Ping interval: 25s, Ping timeout: 60s

AUTHENTICATION MIDDLEWARE:
  - Extracts JWT from socket.handshake.auth.token or Authorization header
  - Verifies with jwtService.verify()
  - Attaches user object to socket: { userId, email, displayName }
  - Rejects connection if no token or invalid token

ON CONNECTION:
  - User automatically joins room: "user:{userId}" (personal room)
  - This room receives messages even when conversation window is not open

SOCKET EVENTS (Client → Server):

  'join-private-conversation' (conversationId: string)
    → Joins socket to room "conversation:{conversationId}"
    → Validates conversationId is non-empty

  'leave-private-conversation' (conversationId: string)
    → Leaves room "conversation:{conversationId}"

  'send-private-message' (data: {conversationId, message, messageType?, messageId?, encryption?})
    → FULL FLOW:
      1. Validates all inputs (non-empty, message length <= 10000 chars)
      2. Looks up conversation in MongoDB to verify user is a participant
      3. If messageType='encrypted' and E2EE is disabled → rejects
      4. TRIPWIRE CHECK: If encryption.fallbackReason present and not encrypted,
         increments e2eeFallbackCount counter and logs warning
      5. REPLAY CHECK: For encrypted messages with messageId, checks if
         messageId already exists in chatMessages → rejects duplicates
      6. Creates message document with unique ID: "msg-{timestamp}-{random6}"
      7. Inserts into chatMessages collection
      8. Emits 'new-private-message' to:
         - Room "conversation:{conversationId}" (all participants in the window)
         - Room "user:{otherUserId}" (personal room, for unread badge updates)
      9. AI CHECK: If the other participant is the AI agent (lancelot-ai@internal.system):
         a. Emits 'user-private-typing' to show AI typing indicator
         b. POSTs to AI_AGENT_SERVICE_URL/ai/chat with:
            - conversationId, message, messageType, encryption, messageId
            - Headers: x-user-id, x-user-email, x-trace-id
            - 30-second timeout
         c. Emits 'user-private-stop-typing'
         d. Creates AI response message with ID: "ai-{timestamp}"
         e. Inserts AI message into chatMessages
         f. Emits 'new-private-message' with AI response to conversation room

  'private-typing-start' (data: {conversationId})
    → Emits 'user-private-typing' to other users in the conversation room
    → Includes userId, userName, conversationId

  'private-typing-stop' (data: {conversationId})
    → Emits 'user-private-stop-typing' to other users in the conversation room

  'disconnect'
    → Logs user disconnection

AI AGENT CONFIGURATION:
  - Email: lancelot-ai@internal.system
  - Service URL: AI_AGENT_URL env var or http://localhost:4001
  - AI user ID is cached after first lookup
  - Timeout: 30 seconds
  - Fallback responses in Hebrew if AI service is down

3.11  END-TO-END CHAT FLOW
--------------------------------------------------------------------------------

STARTING A CONVERSATION:
  1. User clicks chat bubble → ContactsOverlay opens
  2. User clicks on a contact (or AI agent)
  3. ChatManager.handleStartConversation(user)
  4. GraphQL: createOrGetConversation(userId) → returns conversationId
  5. ConversationOverlay mounts at calculated position
  6. Socket: emits 'join-private-conversation' with conversationId
  7. GraphQL: GET_CONVERSATION_MESSAGES loads chat history

SENDING A MESSAGE (User-to-User):
  1. User types in TextArea → typing indicator sent via Socket.IO
  2. User presses Enter → ChatManager.handleSendMessage called
  3. E2EE check: encrypt if available, else plaintext
  4. Socket: emit 'send-private-message' with message data
  5. Server (chat-socket.ts):
     a. Validates inputs and conversation membership
     b. Inserts message into chatMessages collection
     c. Broadcasts 'new-private-message' to conversation room + other user's room
  6. Both clients receive 'new-private-message':
     a. ConversationOverlay appends to messages[]
     b. ChatManager updates conversation list

SENDING A MESSAGE TO AI:
  1-5. Same as user-to-user
  6. Server detects other participant is AI agent
  7. Emits typing indicator for AI
  8. POSTs to AI service at /ai/chat
  9. Receives AI response (with optional encryption)
  10. Stores AI message in chatMessages
  11. Emits 'new-private-message' with AI response
  12. Client renders AI response with purple theme

READING MESSAGES:
  1. ConversationOverlay opens → marks all as read after 1s
  2. New message arrives from other user → marks as read after 500ms
  3. GraphQL: MARK_MESSAGES_AS_READ mutation
  4. Server: updates chatMessages.isRead = true, resets unreadCounts

3.12  E2EE (END-TO-END ENCRYPTION) SYSTEM
--------------------------------------------------------------------------------

FILES:
  - apps/web/src/utils/crypto/e2ee.ts      (encrypt/decrypt, key management)
  - apps/web/src/utils/crypto/keys.ts       (key generation, fingerprints)
  - apps/web/src/utils/crypto/keyStore.ts   (IndexedDB key storage)
  - services/shared/crypto/replay.ts        (replay detection)
  - services/api-gateway/src/config/index.ts (ENABLE_E2EE_CHAT flag)

FEATURE FLAGS:
  - ENABLE_E2EE_CHAT (server): enables/disables E2EE on the API gateway
  - NEXT_PUBLIC_ENABLE_E2EE_CHAT (client): enables E2EE UI
  - NEXT_PUBLIC_E2EE_FALLBACK_WARNING (client): shows toast on fallback

HOW IT WORKS:
  1. Each user generates a NaCl key pair (public + secret) stored in IndexedDB
  2. Public key + fingerprint are stored in the user's profile
  3. When sending a message:
     a. Sender encrypts with: their secret key + recipient's public key
     b. Payload includes: text, conversationId, senderId, messageId, createdAt
     c. Encrypted result is JSON-stringified and sent as message body
     d. messageType is set to 'encrypted'
  4. When receiving a message:
     a. Recipient decrypts with: their secret key + sender's public key
     b. Verifies senderId and conversationId match the envelope
     c. Checks messageId for replay attacks
     d. Verifies sender's key fingerprint hasn't changed
  5. Fallback scenarios (recorded as tripwires on server):
     a. Recipient has no public key → plaintext
     b. Key fingerprint mismatch → plaintext (possible key compromise)
     c. Encryption error → plaintext

TRIPWIRE SYSTEM:
  - Server tracks e2eeFallbackCount when clients fall back to plaintext
  - Logged with reason (key_fingerprint_mismatch, encryption_error, etc.)
  - Exposed via /health endpoint for monitoring
